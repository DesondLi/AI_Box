## 3. 共享 Fixtures 设计

### 3.1 核心 Fixtures 清单

| Fixture 名称 | 范围 | 用途 |
|-------------|------|------|
| `empty_kernel` | function | 干净的 MicroKernel 实例，无插件注册 |
| `kernel_context` | function | 已初始化的 KernelContext，包含核心服务 |
| `empty_message_bus` | function | MemoryMessageBus 空实例 |
| `temp_config` | function | MemoryConfig 实例，测试后自动清理监听器 |
| `mock_plugin_factory` | function | 可配置的 Mock 插件工厂（支持失败注入） |
| `tracker_logger` | function | 带日志捕获的 ConsoleLogger，可断言日志内容 |
| `event_loop` | session | 复用事件循环，加速异步测试 |

### 3.2 Fixture 实现规范

```python
# tests/conftest.py

import pytest
import asyncio
from typing import Callable
from kernel.core.kernel import MicroKernel
from kernel.core.memory_message_bus import MemoryMessageBus
from kernel.core.memory_config import MemoryConfigRegistry
from kernel.core.console_logger import ConsoleLogger

@pytest.fixture(scope="session")
def event_loop():
    """全局事件循环，加速异步测试"""
    loop = asyncio.new_event_loop()
    yield loop
    loop.close()

@pytest.fixture
def temp_config():
    """临时配置注册表，测试后自动清理监听器"""
    config = MemoryConfigRegistry()
    yield config
    # 清理所有 watchers
    config._watchers.clear()

@pytest.fixture
def tracker_logger():
    """可捕获日志的 logger 实例"""
    class TrackerLogger(ConsoleLogger):
        def __init__(self):
            super().__init__()
            self.logs = []
        def _log(self, level: str, message: str, **kwargs):
            self.logs.append((level, message))
            super()._log(level, message, **kwargs)
    return TrackerLogger()

@pytest.fixture
def mock_plugin_factory():
    """Mock 插件工厂，支持依赖注入和失败模拟"""
    from tests.unit.test_helpers import MockPlugin
    def factory(plugin_id, deps=None, fail_at=None):
        return MockPlugin(plugin_id, deps or [], fail_at)
    return factory
```

## 4. 测试用例设计规范

### 4.1 命名规范
```
test_<模块>_<行为>_<预期结果>

示例：
- test_config_set_triggers_watcher
- test_logger_error_level_includes_warning
- test_plugin_error_chaining_preserves_stack
```

### 4.2 Given-When-Then 结构
```python
def test_config_watch_callback_receives_updates(self, temp_config):
    """Given: 已注册监听器的配置
    When: 配置值发生变更
    Then: 监听器回调被触发，收到新值
    """
    # Arrange
    called = []
    def callback(key, value):
        called.append((key, value))
    
    temp_config.watch("test/*", callback)
    
    # Act
    temp_config.set("test/key", "new_value")
    
    # Assert
    assert len(called) == 1
    assert called[0] == ("test/key", "new_value")
```

### 4.3 边界用例覆盖清单

| 场景 | 测试要点 |
|------|---------|
| 空值处理 | None / 空字符串 / 空列表 |
| 异常值 | 类型错误 / 范围越界 / 非法字符 |
| 并发场景 | 多协程同时读写 / 竞态条件 |
| 资源泄漏 | 订阅/监听后是否正确清理 |
| 幂等性 | 重复调用是否产生副作用 |
| 错误恢复 | 异常发生后状态是否一致 |

## 5. 测试优先级与实施顺序

### 阶段 1：基础设施搭建（优先级 P0）
1. 创建 `tests/conftest.py` - 核心 fixtures
2. 创建 `tests/unit/test_helpers.py` - 通用 Mock 基类
3. 调整 `pytest.ini` 启用覆盖率阈值

### 阶段 2：核心组件补全（优先级 P0）
1. `test_memory_config.py` - KV 操作 / watch 机制 / 命名空间
2. `test_errors.py` - PluginError / Result 类型完整测试

### 阶段 3：基础组件补全（优先级 P1）
1. `test_console_logger.py` - 日志级别 / 格式化 / 子日志器
2. `test_message_bus.py` - 内部方法补充 / 边界场景

### 阶段 4：规范化与质量增强（优先级 P2）
1. 迁移现有测试到 `integration/` 目录
2. 补充 Kernel 剩余方法测试
3. 启用 `--cov-fail-under=80`
4. 添加性能基线断言

## 6. 质量增强措施

### 6.1 CI 集成配置
```ini
# pytest.ini 更新
addopts = -v --tb=short --strict-markers --cov=kernel --cov-report=term-missing --cov-fail-under=80 -W error::DeprecationWarning
```

### 6.2 泄漏检测
每个涉及资源（watcher、subscription）的测试后，自动检查是否有残留：
```python
def teardown_method(self):
    assert len(self.config._watchers) == 0, "Watcher leak detected"
```

### 6.3 性能基线
对高频操作添加性能断言：
```python
import time

def test_message_bus_performance(self):
    bus = MemoryMessageBus()
    start = time.perf_counter()
    
    for _ in range(1000):
        await bus.publish("test/topic", {"data": 1})
    
    elapsed = time.perf_counter() - start
    assert elapsed < 0.1, "Message delivery too slow"
```
